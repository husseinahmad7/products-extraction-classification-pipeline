Extract a record. Inspect the evidence. Replay the result.

Evidence Pipeline turns a retained HTML, JSON, or canonical PDF capture into schema-validated records with field-level provenance. Start offline with the checked-in examples; then add a source and operate the service when you need durable jobs and review.

Development alphaBounded HTML/JSON acquisition, link discovery, interval scheduling, and offline replay are implemented. Live browser/PDF acquisition, classifier activation, and the release benchmark remain unfinished.

Run the offline example

Python 3.12 or 3.13

Clone the repository, then run these commands at its root. No account, API key, browser, model, or GPU is needed.

python -m pip install -e .
product-pipeline validate examples/catalog-recipe.yaml
product-pipeline extract examples/catalog-recipe.yaml examples/catalog.json --output catalog-result.json
product-pipeline replay examples/catalog-recipe.yaml examples/catalog.json catalog-result.json

The result file contains records, field evidence, capture and recipe hashes, and any quarantine reasons. A second documentation example exercises the same engine on a different schema.

What the result proves

Evidence and replay

Each output field carries its locator, raw value, transform path, outcome, and capture hash. The engine distinguishes missing, null, observed, and derived values. Invalid records and conflicting identities are quarantined instead of being silently published.

1

Capture

Retain the source bytes under a content hash.

2

Extract

Apply a versioned recipe and validate against the target schema.

3

Replay

Re-run retained bytes and compare deterministic result hashes.

Offline replay verifies the current engine against retained bytes. Reproducing an old retained OCI runtime is a separate, unfinished release requirement. See the architecture and invariants.

Recipes are data

Developer reference

A recipe names the source, record scope, identity fields, locators, transforms, and target JSON Schema. New supported sources can be configured without writing a vendor-specific extractor class. The language is bounded: it does not execute arbitrary Python or JavaScript.

mode: json
record_scope: {type: items_path, value: "$.items[*]"}
identity_fields: ["/sku"]
fields:
  /name:
    locator: {type: json_pointer, value: /name}
    transforms: [{op: strip}]
    required: true

Supported inputs include offline HTML, JSON, rendered-HTML captures, and canonical PDF text blocks. Live acquisition supports HTML/JSON with bounded link navigation and an HTTPS bearer token from an environment reference. This is not a general login-flow or browser/PDF acquisition system.

Run the service locally

Operator setup

The API, durable worker, and React dashboard share one workspace. Use PostgreSQL for multi-worker evaluation; SQLite is a single-process development convenience.

uv sync --frozen --extra server --extra dev --python 3.13
uv run --no-sync product-pipeline migrate
uv run --no-sync product-pipeline admin-bootstrap

# Start these in separate terminals:
uv run --no-sync product-pipeline serve
uv run --no-sync product-pipeline worker

# In dashboard/:
npm ci --ignore-scripts
npm run dev

Bootstrap prints a token once in an interactive terminal. Open the URL printed by Vite and enter that token. The dashboard holds it in browser memory. For the development Compose stack, set POSTGRES_PASSWORD in .env, run docker compose up --build -d, and bootstrap inside the API container.

The Compose stack binds the API to host loopback. It is a development deployment, with no claim of Internet-ready TLS, isolated browser/PDF workers, or coordinated backup. Read the operator runbook before using it with source data.

Review and recovery

Durable jobs

Operations return an ID and a state. A successful operation can still produce an invalid recipe or an extraction awaiting human review, so inspect the referenced resource before treating a run as publishable.

Common states and the next operator action
StateMeaningNext action
QueuedWaiting for a worker claim.Poll the operation.
PausedQuota or another explicit hold stopped progress.Provision capacity, expand the accounting limit, then resume.
Review requiredA recipe or removal needs a human decision.Inspect evidence and record a reasoned approval or rejection.
FailedThe operation ended with an error.Read the error and audit trail before retrying with a new key.

Mutations use Idempotency-Key; versioned decisions use the current ETag in If-Match. Reuse the same idempotency key if a network failure leaves a request outcome uncertain. The runbook documents quota and token recovery.

Release status

Gate blocked

This repository is a development alpha. The Python SDK/CLI, evidence engine, PostgreSQL worker, interval scheduler, dashboard, packaging, and guarded release workflow are implemented. The full approved release still requires hardened live browser/PDF acquisition, broader review and storage controls, rendered browser verification, coordinated restore, and an independently adjudicated classification benchmark.

Classification suggestions abstain until certification. The 52-record AI-reviewed diagnostic measures agreement with proposals. A separate 663-title building-materials diagnostic used publisher source-list categories and a different taxonomy; its labels were not independently adjudicated release gold. Laya is not promoted. Model experiments run on Kaggle; no model weights are shipped through this site or repository.

CI, images, and publication

Release engineering

CI runs Python 3.12/3.13 on Linux and Windows, PostgreSQL 17 integration, S3-compatible RustFS checks, a built-container smoke test, dashboard checks, dependency audits, and an SBOM. The version-tag workflow verifies a signed tag and the release manifest before publishing. It remains blocked by unfinished capabilities and the independent benchmark.

This GitHub Pages site contains static documentation only. It does not host the operator dashboard or service. To evaluate locally, follow the quickstart above; to operate a development stack, use the runbook. Publishing a Python package or container image also requires protected GitHub environments and registry configuration.
