# GitHub Pages documentation brief

Mode: Read. Audience: developers first, operators second. The reader should be able
to run the two offline examples, understand retained field evidence and the
single-workspace alpha boundary, then find operating and release details. The
source of truth is the repository's README, architecture, runbook, benchmark
protocol and implementation status. No unverified performance, production or
classification claims belong on the site.

## Direction contract

THESIS: A short path from a runnable capture to its evidence and replay. The docs
site extends the existing Evidence Docket world and puts a concrete example
ahead of broad product description.

OWN-WORLD: Ink-blue navigation, cool workspace, white reading paper, fine rules,
violet actions, explicit state words and system typography. Monospace is for
commands, paths and hashes. Flat surfaces carry the reading order.

STORY: Install, validate a recipe, extract a canonical capture, replay it, then
understand what the evidence proves. Operators can follow the separate service
path, quotas, recovery and release gates.

FIRST VIEWPORT: A compact navigation rail and a wide article begin with the
offline quickstart. The command sequence and a small, explicitly illustrative
field-evidence specimen are visible without scrolling on a common desktop.
On narrow screens, navigation becomes a short scrollable row and the article fills
the viewport.

FORM: Established-world docs shell extension; no concept seed or new visual
world. The signature interaction is anchored wayfinding between commands,
evidence, operations and status. Motion is limited to focus and selection state.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

No raster imagery is required. GitHub Pages publishes only static public docs;
the site cannot expose the operator dashboard or authenticate to the service.
