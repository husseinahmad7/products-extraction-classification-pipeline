## Verification boundary

### Public-beta implementation (not launch acceptance)

The beta adds trusted Ed25519 issuer/JWKS verification, personal workspace derivation, operator-only domain decisions, HTTPS/credential-reference restrictions, monthly API/job/source/runtime/read-byte admission and lifetime metadata/artifact storage budgets. PostgreSQL row locks serialize admission across tenants. Metadata reservations account conservatively for idempotency and audit copies; corrections reference retained records rather than duplicating their contents. Snapshot exports reconstruct and verify those references, preserve provenance, and accept an explicit subset of latest correction IDs when a taxonomy exceeds 1000 reviewed records. Model registration is per-workspace metadata only, with no weight load or activation path.

Public workers exit on idle and checkpoint batch-deadline recovery. Schedules must pass admission before a run/job is created; denied schedules pause with an audit reason. The dashboard refreshes operation status only while visible, with a bounded polling window. Public startup/liveness do not query PostgreSQL; `/health/ready` is disabled in public mode to avoid unauthenticated database wakeups.

The final local Python 3.12 suite passed with **199 tests passed, 19 service-dependent skips, and 84% line coverage**. The expanded learning/ownership assertions then passed in a separate 19-test run. Ruff, mypy, frozen lock validation, generated schemas and wheel/source-distribution builds passed. Native dependency/startup probes passed locally. The dashboard's clean install, TypeScript/production build, 25 component tests and full dependency audit passed; these are not rendered browser/accessibility results. Beta-specific real PostgreSQL race/ownership/immutability checks and service probes are added to CI but have not yet run remotely. The new source and updated Pages content remain local; earlier alpha CI and publication do not verify these changes.

A free-plan Neon project and managed Auth were provisioned. A provider SQL-bridge `SELECT 1` succeeded, and the management API reported suspension 317 seconds after that activity. That observation uses a different client, not the deployed worker. Workstation PostgreSQL connections failed on both direct and pooled endpoints: locked-client TLS/cold-start/migration and end-to-end suspension/resume acceptance remain unverified. Managed Auth email-verification/trusted-origin configuration and Neon object-store conditional-write/SSE/hash probes remain launch gates. Wasmer account authentication succeeded through a read-only query, but exact WASIX dependency resolution failed for locked native versions; the [sanitized compatibility report](../deploy/wasmer/compatibility-report.json) records the missing pins. No dependency downgrade, package upload, deployment or paid action was performed. In-app Browser and connected Edge initialization timed out, so no rendered dashboard sign-off is claimed.

Private Kaggle trained comparisons completed for TF-IDF, trained SetFit, GLiClass-edge and base/fine-tuned Laya. The [clean CPU report](../benchmarks/reports/training-comparison-kaggle-v4.json) retains the same already-inspected 155-record exploratory test: macro-F1 0.621/0.723/0.086/0.554/0.654. The [preceding repeat](../benchmarks/reports/training-comparison-kaggle-v3.json) measured fine-tuned Laya at 0.617. Neither repeat is selected as independent certification, and no model is promoted. Generic snapshot training/export ingestion is implemented but awaits a suitable independently reviewed frozen corpus.

### Earlier development-alpha evidence

The latest full local Python 3.13 suite completed with **92 passed, 12 skipped, and 83% line coverage**. The skipped cases require PostgreSQL or an S3 endpoint unavailable locally. The [alpha pull-request CI run](https://github.com/husseinahmad7/products-extraction-classification-pipeline/actions/runs/36417238142) passed Python 3.12/3.13 on Linux and Windows, PostgreSQL 17 integration/migration checks, RustFS-backed S3 integration, the complete Docker Compose smoke test, dashboard build/tests/audit, documentation validation, dependency audit and SBOM generation. The S3 test covers content-addressed round-trip/idempotence, missing/invalid keys and tamper detection against RustFS, not every S3 implementation. Ruff, formatting, generated schemas, mypy and wheel/source-distribution builds passed in CI. None of these is a rendered browser or production deployment sign-off.

After explicit permission to upload backend code and tests (no credentials, datasets or model files), **seven PostgreSQL integration cases passed on Kaggle**, including a newly added real process-death recovery case. The PostgreSQL 17.11 run also passed five additional eight-writer quota-race repetitions, migration repeatability/drift checks, and the seven-case suite after a database-only backup/restore. [The retained report](../benchmarks/reports/postgres-integration-pg17.json) identifies private notebook version 2 and the exact source bundle/per-file hashes. [Version 1](../benchmarks/reports/postgres-integration-pg14.json) also passed on PostgreSQL 14.24. These are seven distinct cases with repetitions, not 19 distinct tests. Object-store recovery, coordinated service restore and production security isolation are still unverified.

Local verification uses Python 3.13 and Node 24. Python 3.12's local interpreter encountered a native environment crash, so no local 3.12 pass is claimed, though both 3.12 CI matrix jobs passed. Docker/PostgreSQL services were unavailable on this workstation; GitHub Actions exercised them with disposable services. Browser capture/control remained unavailable because of the Windows sandbox ACL-helper failure; static design review and component tests are not a rendered dashboard visual or accessibility sign-off.

The Kaggle Laya infrastructure smoke completed on a T4. The separate AI-reviewed exploratory diagnostic is not the required comparative release benchmark. Read the machine-readable reports for exact status; neither synthetic examples nor AI labels can satisfy the independent-gold certification gate.

A further [external building-materials diagnostic](../benchmarks/reports/external-building-diagnostic.json) completed on a private Kaggle T4 notebook. It deduplicated 861 Hong Kong Buildings Department list rows to 663 titles across 250 manufacturer groups, then used manufacturer-disjoint train/calibration/test splits of 406/102/155. On the 155-title test split, trained TF-IDF linear reached 0.621 macro-F1, Laya 0.554, frozen embeddings 0.478, and taxonomy TF-IDF 0.129. Categories were inherited from source lists rather than independently adjudicated product labels, and the five-class title-only task differs from the original two-vendor taxonomy. This is diagnostic evidence, not release gold; classifier auto-accept remains disabled and the release gate remains blocked.

`benchmarks/release-manifest.json` remains `blocked`. Its capability booleans mean **verified for the approved full release**, not merely present in alpha source; implemented-but-unverified navigation, scheduling and throttling therefore remain false there. The alpha source is public on [pull request #1](https://github.com/husseinahmad7/products-extraction-classification-pipeline/pull/1) and CI has run remotely. Static documentation deploys separately from `main` through GitHub Pages; no package, image, hosted API or SaaS deployment is implied or published.
